# 开源 Agent 工作区调研与 Facai 采纳方案

更新时间：2026-10-02。调研目标是借鉴成熟项目中适合 Facai 的运行机制，不将第三方项目整库复制进 Facai。

## 主要参考：Sim

[Sim 仓库](https://github.com/simstudioai/sim) 将自己定位为可构建、部署、监控 Agent 与工作流的开源工作区；仓库标注 Apache-2.0，但官方文档说明部分企业功能另有许可条件。实际复制任何代码前仍需逐文件核对版权头、依赖许可证和功能许可。

[官方工作流执行说明](https://docs.sim.ai/workflows/how-it-runs)描述了按依赖关系运行节点：互相独立的分支可同时执行；汇合节点等待已选分支；条件分支、循环和并行容器决定执行路径。失败会停止新节点，并可通过显式错误路径处理。

[官方运行日志说明](https://docs.sim.ai/logs-debugging)把每次运行记录为可审查事实，包括触发来源、节点顺序、逐节点输入/输出/耗时/错误；[运行 API](https://docs.sim.ai/api-reference/workflows/executeWorkflowV2)还支持异步回执、状态查询、流式事件和运行 ID 防重复。

视频中可辨认的产品方向（视觉编排、模块/API 集成、监控日志、隔离执行）与上述官方资料大体相符；视频里的“1000+ 集成”等宣传数字不作为 Facai 的已验证指标。

## Facai 已有基础与差距

- 已有：mission 隔离、原话与专业提示分开保存、逐事件时间线、整数百分比、SQLite 持久队列/租约、跨 mission 并发、OpenCode 实时输出、成本归属、n8n webhook 与幂等回调。
- 主要差距：步骤目前是有序列表而非依赖图；没有成熟的分支汇合/条件/可恢复节点语义；正在运行阶段只有粗粒度进度，缺少逐节点耗时与输入输出检查器；大型流程需要持久化的工作流版本与执行快照。
- 安全差距：同一 mission 的共享工作区只能串行写入。需要并行编程任务时，应使用每个子任务独立 worktree/沙箱，经过验证的合并步骤再更新主工作区；不能为了 UI 上看起来“多线程”而并发写一个目录。

## 采纳优先级

1. **现在：**保留当前轻量栈，将线性阶段增强为可视化节点流；所有状态/百分比来自持久事件，错误和输出可定位回对应阶段。
2. **下一步：**以可选依赖图支持独立分支并行、汇合等待、失败传播；保持旧 mission 的线性步骤兼容，并限制并发与重试。
3. **随后：**补充逐阶段耗时、输入/输出摘要、运行快照、幂等运行标识及明确的暂停/恢复审批事件。
4. **集成扩展：**优先让 n8n 承接成熟的外部系统连接和确定性流程；Facai 保留 mission 隔离、Agent 选择、消息原话、可视化跟踪和权限边界。避免立即引入 Sim 的 Next.js/Bun/Postgres/实时服务器整套架构。

## 结论

最值得借鉴的是 **依赖驱动执行 + 可检查的逐节点运行记录 + 真实异步状态**，而非复制品牌 UI 或庞大集成目录。以兼容性和任务隔离为先，逐步将这些运行语义落入 Facai 现有 FastAPI/SQLite 架构。
